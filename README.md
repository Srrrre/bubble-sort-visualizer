# 冒泡排序可视化

用原生 HTML、CSS、JavaScript 做的中文算法学习网站。通过柱状图逐步观察相邻元素的比较与交换，适合学过 C/C++、正在入门网页开发的同学。

不需要安装 Node.js、Python，不需要后端、API Key 或联网。默认数组为 `5, 3, 8, 2, 6`。

## 本地打开

1. 下载本仓库的 ZIP 并**完整解压**，或使用 Git 克隆仓库。
2. 双击 `index.html`；也可以右键选择「打开方式 → Microsoft Edge」。
3. 点击「开始排序」。HTML、CSS、JS 必须保持在同一个目录。

## 功能

- 自定义 2～20 个 1～100 的整数；支持英文逗号、中文逗号和空白分隔。
- 输入有误时给出具体中文说明，并保留画布中的有效数组。
- 随机生成 10 个整数，允许重复。
- 逐次显示比较、交换或不交换，每轮结束标记已就位元素。
- 整轮没有交换时提前结束；完成时所有元素均标记为已就位。
- 开始、暂停/继续、重置；暂停期间连位置移动动画也会冻结。
- 100～1500 毫秒/步的速度调节，向右拖动更快。
- 当前轮次、实际比较与交换次数，以及中文步骤说明。
- 标签、符号与颜色共同表达状态；键盘焦点、禁用按钮样式、减少动态效果支持。
- 适配手机；数组较长时只在画布内部横向滚动。
- 页面下方附 C++ 参考代码及算法原理。

## 实现思路：算法和播放分开

### 先阅读这三个位置

1. **`parseArray(text)`**：把输入拆成数字，检查数量、整数格式和范围。先完整校验再替换数组，避免输入错误破坏原数据。不能用 `parseInt()` 直接校验，因为它会把 `2abc` 截断成 `2`。
2. **`bubbleSortSteps(input)`**：使用与 C++ 相同的两层循环。`function*` 定义生成器，`yield` 暂停函数并交出一个步骤；播放器调用 `.next()` 才执行下一步。比较和交换分别产生步骤，不交换也会产生说明。没有使用内置 `sort()` 实现排序。
3. **`scheduleNext()` / `advanceStep()`**：一次只用一个 `setTimeout` 安排下一步，在回调中读取生成器并更新画布。旁边的 `togglePause()`、`cancelPlayback()` 和 `reset()` 管理暂停、取消和恢复。

### 数据怎样流动

```text
输入 → parseArray 校验 → 当前数组
                            ↓ 开始
                  bubbleSortSteps 生成步骤
                            ↓ next()
                  advanceStep → showStep → 画布与统计
                            ↑
                  setTimeout 等待下一步
```

每个步骤含有数组快照、比较位置、已排序后缀的起点、轮次、累计比较/交换次数和说明。数组快照让已产生的步骤不会被后续交换修改。网页按需消费步骤，不预先保存全部动画帧。

`state` 集中保存当前数组、开始前的数组副本、播放状态、生成器和定时器。状态仅有 `idle`、`running`、`paused`、`completed` 四种。排序和暂停期间锁定数组编辑；同时在事件处理函数中检查状态，防止重复开始。

暂停会清除定时器、冻结 Web Animations 并保留生成器位置。继续后从当前步骤等待一个完整间隔，再执行下一步。重置会递增任务编号 `runId`、清除定时器和动画；旧回调即使已排队，也无法通过编号检查。

柱高为 `数值 / 当前最大值 × 210px`。画布固定高度，数值始终显示在柱子上方。交换时保留柱子对应的 DOM 节点，通过 Web Animations 从旧位置移动到新位置。系统选择“减少动态效果”时省略位移动画，算法步骤不变。

### 几个操作约定

- 修改输入框后，需要按「应用数组」或在输入框按 Enter，才会更新画布。
- 「重置」恢复到**本次点击开始前**的数组，并清零统计；应用新数组或随机数组后，也会将其设为新的起点。
- 完成后「再次排序」会排序画布上当前的数组，所以一般会在第一轮提前结束。要重看刚才的过程，先「重置」，再「开始排序」。
- 调速对后续步骤生效，已经安排好的当前等待不会突然跳过。
- 图上的轮次从 1 开始，下标从 0 开始；待开始时轮次显示 0。

## 测试与验收

网站本身无需测试工具。以下命令只供继续开发时使用。

算法测试使用 Node.js 自带的测试器：

```powershell
node --test tests/algorithm.test.js
```

浏览器测试额外需要 Playwright 和 Microsoft Edge。可在已有 Playwright 的环境运行：

```powershell
node tests/browser.test.cjs
```

如果 Playwright 不在默认模块搜索路径，设置 `PLAYWRIGHT_MODULE` 为已安装的 `playwright` 包目录后再运行。浏览器测试和截图不是网站运行所需文件。

2026-10-07 实际验证结果：

- **35 项算法测试通过**，含默认、升序、逆序、重复、全相同、2 个、20 个元素，以及 95 组确定性随机输入；检查升序、元素多重集不变、相邻步骤顺序、真实计数、输入快照和提前结束。
- **16 项 Edge 浏览器验收通过**，使用 Microsoft Edge 154.0.4258.62，通过 `file://` 打开本地网页，并拦截网络请求确认核心功能无外部依赖。
- 验证了输入错误保留原数据、随机数组范围、重复开始、忙时锁定、暂停/恢复、调速、重置取消旧任务和完成后再次开始。
- 长数组使用浏览器虚拟时钟加速验收；另有真实计时器与 Web Animations 测试，确认交换中暂停后位置、数组、计数和说明不变，恢复后正常完成。
- 检查了 1280、390、320 像素宽度；页面本身不横向溢出，20 个柱子在画布内滚动。桌面与手机截图已实际查看，键盘焦点、Enter 应用数组和减少动态效果模式也已测试。
- 验收过程中没有控制台错误、未捕获异常或外部网络依赖。

**尚未验证：**真实手机触摸设备、Safari/Firefox、屏幕阅读器和旧版浏览器。手机检查为桌面 Edge 模拟窄屏，不能代替真实设备验收。

手动复验：

1. 用默认数组排序，结果应为 `2, 3, 5, 6, 8`，比较 **10 次**、交换 **5 次**。
2. 分别输入 `1,2,3,4,5`、`5,4,3,2,1`、`4,2,4,1,2`、`7,7,7,7`、`100,1` 和 20 个数，观察每一轮和最终数量、重复值。
3. 尝试空白、`1,abc`、`1,2.5`、`1,101`、`1` 及 21 个数，确认错误说明明确且画布不变。
4. 连续点击开始；排序中暂停，等待数秒，确认柱子、计数和说明不变。继续后应从原处播放。
5. 排序和暂停时尝试修改数组，控件应禁用；调整速度后观察后续间隔变化。
6. 交换时点击重置，再等数秒，确认原数组和零计数不再被旧任务改变。再次开始应可正常完成。
7. 完成后再次排序、重置、应用新数组和随机生成均应可用；随机数组应恰好有 10 个 1～100 的整数。
8. 手机窄屏输入 20 个数，在画布内左右滚动；电脑用 Tab 切换控件并查看焦点边框。

## 已知限制

- 第一版只演示冒泡排序，没有单步按钮、历史回放或数据持久化；刷新页面恢复默认数组。
- 步骤间隔是目标时间，后台标签页、设备性能或浏览器节流可能延长等待。
- 支持现代浏览器，主要以 Microsoft Edge 验收；未针对旧版 Internet Explorer 做兼容处理。
- 冒泡排序本身平均和最坏时间复杂度为 O(n²)，有提前退出时最好为 O(n)。C++ 原地算法额外空间为 O(1)；网页为数组副本、步骤快照和柱子节点使用 O(n) 额外空间。
- 20 个逆序元素需 190 次比较和 190 次交换；最慢速度下整个演示需要数分钟，这是逐步展示的正常结果。
