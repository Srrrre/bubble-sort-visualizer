# 算法与数据结构可视化

用原生 HTML、CSS、JavaScript 做的中文算法学习网站。包含冒泡排序、无哨兵单链表与二叉树遍历三个模块，适合学过 C/C++、希望看清算法、指针和递归调用过程的同学。

不需要安装 Node.js、Python，不需要后端、API Key 或联网。默认数组为 `5, 3, 8, 2, 6`。

## 本地打开

1. 下载本仓库的 ZIP 并**完整解压**，或使用 Git 克隆仓库。
2. 双击 `index.html`；也可以右键选择「打开方式 → Microsoft Edge」。
3. 默认进入冒泡排序。点击顶部「数据结构 → 单链表」或「数据结构 → 二叉树」切换；选择操作后点「开始演示」或「下一步」。HTML、CSS、JS 必须保持在同一个目录。

在线入口：[冒泡排序](https://srrrre.github.io/bubble-sort-visualizer/) · [单链表](https://srrrre.github.io/bubble-sort-visualizer/#linked-list) · [二叉树](https://srrrre.github.io/bubble-sort-visualizer/#binary-tree)。仓库仍为 [Srrrre/bubble-sort-visualizer](https://github.com/Srrrre/bubble-sort-visualizer)，没有重命名或另建仓库。

## 二叉树模块

第一阶段实现前序、中序、后序和层序遍历。默认输入 `[1,2,3,4,5,null,6]`：根为 1；左孩子 2 有孩子 4、5；右孩子 3 只有右孩子 6。

### 创建和使用

1. 输入层序序列，点「创建二叉树」或按 Enter。必须使用成对英文方括号和英文逗号；`null` 表示空孩子，`[]` 或 `[null]` 表示空树。支持 -99～99 的整数、0 和重复值，最多 15 个实际节点。
2. 解析时将左右孩子依次分配给**真实存在的父节点**。例如 `[1,null,2,3]` 表示 1 的右孩子为 2，2 的左孩子为 3；并非完全二叉树的数组下标规则。省略末尾未给出的孩子等同为空；若已无可用父节点，后面的数字或 null 都会报错。
3. 空输入、小数（含 `1.0`）、科学计数法、非法字符、越界数字、超过节点上限和多余位置均显示具体错误，原树及有效教学进度保留。
4. 选择遍历方式，先点「下一步」，观察函数进入、空指针判断、访问、子调用、返回与父函数恢复。自动播放期间禁用单步；暂停后可以继续单步或自动播放。
5. 速度范围 100～1500 毫秒/步，向右更快，对后续等待生效。暂停保留整个教学步骤；继续后等待一个完整间隔再推进。
6. 「重置」保留遍历前的完整树并清空进度。切换遍历方式会取消旧任务；切到其他模块会取消未完成的演示，完成的结果可保留。输入和创建按钮在运行、暂停时禁用，遍历选择器始终可切换。

| 遍历 | 顺序与特点 | 默认结果 | 时间 / 算法辅助空间 |
| --- | --- | --- | --- |
| 前序 | 根 → 左 → 右，确认非空后先访问自己 | 1 → 2 → 4 → 5 → 3 → 6 | O(n) / O(h) |
| 中序 | 左 → 根 → 右，左调用返回后才访问自己 | 4 → 2 → 5 → 1 → 3 → 6 | O(n) / O(h) |
| 后序 | 左 → 右 → 根，两个子调用返回后才访问自己 | 4 → 5 → 2 → 6 → 3 → 1 | O(n) / O(h) |
| 层序 | 先进先出队列，每层从左到右 | 1 → 2 → 3 → 4 → 5 → 6 | O(n) / O(w) |

n 为节点数，h 为树的最大深度，w 为最大层宽。树深度以根为 1、空树为 0。界面的**递归深度等于当前栈帧数**，包含短暂的 nullptr 调用，因此可能是 h+1。JavaScript 可视化为当前快照、访问记录和 SVG 另需 O(n) 空间，每步复制、数组队列移除与渲染也有额外工作；这与上表的 C++ 遍历算法成本分开计算。生成器按需产生下一步，不存储完整历史；若将来保存全部 O(n) 个快照，最坏需 O(n²) 空间。

### 递归调用栈与 BFS 队列如何同步

- 数据模型用 `nodes` 节点表与稳定的 T1、T2 等引用保存 `left`、`right`、`root`。ID 在同一棵树的遍历、重置中不变，重复值也能区分；重新创建树会重新分配 ID。ID 不是真实内存地址。
- `traversalSteps()` 内部的 `walk()` 是真正的递归生成器。`yield* walk(child)` 运行完整个子调用后，父函数才继续。进入压栈、非空判断、访问和返回分别产生不可变步骤快照；nullptr 也入栈、判断、返回。
- 子函数执行到末尾时仍展示自己的栈帧与代码行；下一步弹栈并恢复父帧，高亮父函数刚完成的调用语句。再下一步才执行父函数后续语句，防止把“返回”误画成“重新进入父函数”。
- `visitedIds` 只在实际 `visit` 时增加；“已完成”表示本节点的子调用都结束、函数即将返回。栈顶、树上当前节点、代码行、说明和结果都来自同一个步骤对象。栈顶在上方，其余栈帧显示等待左/右子树的状态。
- BFS 使用真实 FIFO 队列。读取队首、出队、访问、检查左孩子、左入队、检查右孩子、右入队分别展示；空孩子不入队。队头在左，队尾在右，结果中也显示节点 ID。循环结束时队列为空。
- SVG 坐标由树结构确定：中序布局分配横坐标、层数决定纵坐标；这只负责排布，并不决定动画的访问顺序。固定间距避免重叠，宽树和深树均在图形区内部滚动。节点颜色、边框、文字标签和图例共同表示状态。
- 播放器保持一个定时器和任务编号；取消、重置、切换时旧编号失效。暂停不调用生成器、不重画教学内容，所有关系图、栈/队列和代码行保持不变。

### 二叉树最值得先读的三个函数

1. **`createTree(tokens)`，binary-tree-core.js：**按真实父节点的队列分配左右孩子。可对照 C++ 的 `queue<TreeNode*>` 理解为何遇到 null 时不把空位置继续当作父节点。
2. **`traversalSteps(original, operation)`，binary-tree-core.js：**重点看内层 `walk()` 的 `yield*` 与 `stack.pop()`。与 C++ 递归一样，调用子函数会等待它返回；不同遍历只改变 visit、left、right 的次序。该函数的层序分支则展示队列的先进先出。
3. **`advanceOneStep()`，binary-tree.js：**每次只调用一次生成器 `.next()`，再用同一个快照更新树、栈或队列、代码与说明。它把算法执行过程与网页播放速度分开，`scheduleNext()` 只是安排何时消费下一步。

推荐学习路线：选择中序，对默认树反复单步，直到首次访问 4；确认 1、2 虽然已经进入函数，却还没加入结果。然后看 4 的左空调用返回到 `inorder(root->left)`，再执行 `visit(root)`。后序中观察两个子树都返回后才输出根 1；最后切层序比较“函数栈”与“先进先出队列”。

## 单链表模块

默认展示 `head → 10 → 20 → 30 → 40 → nullptr`，没有哨兵节点。每张卡片区分 `val` 和 `next`；箭头始终按照实际引用绘制。head 是指针标签。N1、N2 等编号标识节点身份，不是真实内存地址，也不随位置变化；横向排列不代表内存连续。

### 操作方法与规则

- **创建：**输入 1～12 个 -99～99 的整数，支持中英文逗号、空格，允许重复值、0 和负数。错误输入保留原链表；创建空链表使用「清空链表」。随机生成 5～8 个合法节点。
- **遍历：**观察 p 从 head 沿 next 移动，逐步记录已访问的值，直到 nullptr。
- **查找：**输入目标值，只返回第一个匹配节点及其从 1 开始的位置；不存在时明确显示“未找到”。
- **插入：**长度 n 时合法位置为 1～n+1；1 是头插，n+1 是尾插。先寻找前驱、旁置分配节点，再连接后继，最后修改前驱或 head。
- **删除：**合法位置为 1～n。先用 target 保存目标，让前驱或 head 绕过它，再展示脱离与模拟释放。释放后的 target 会短暂标为悬空（不可访问），下一步 `target = nullptr` 才真正置空；C++ 的 delete 本身不会自动清空指针。空链表不能删除。
- **反转：**使用 prev、curr、next 三个指针，每轮分别保存后继、改向 next、前进 prev、前进 curr，最后更新 head。过程中保留固定节点位置，暂时不可从 head 到达的存活节点仍全部显示。

「下一步」在待开始时准备当前操作并执行第一步，在暂停时只推进一个教学步骤。自动播放期间禁用单步与结构输入，暂停不会改变节点、箭头、代码高亮或说明。速度向右更快，对后续等待生效。

「重置本次操作」恢复操作开始前的节点 ID、值、next、head、长度及编号分配器。完成后可以直接在结果上选择下一项操作；更换操作后，新的重置起点取当前链表。切到其他模块会回滚未完成的链表操作；完成后的结果会保留。离开正在播放的冒泡排序模块也会终止并重置该排序。

### 最值得先读的三个位置

在 `linked-list-core.js` 的 `operationSteps()` 中：

1. **`operation === 'insert'` 分支：**先修改 `newNode.next` 保存原后继，再修改 `prev.next` 或 `head`。两次引用修改分别产生可观察的快照，完成后才整理布局。
2. **删除分支的 `bypassLine` 附近：**target 先保留待删节点，前驱绕过它，随后展示脱离和释放。这里的 JavaScript `delete model.nodes[target]` 只移除教学模型中的记录；真实内存由垃圾回收器管理，并不等于 C++ 的手动内存释放。
3. **反转分支的 `pointers.next = model.nodes[pointers.curr].next` 附近：**如果先覆盖 curr.next，就失去了原来的后继。next 保存这条去路，因此当前连接反向后仍能继续处理后半段。

C++ 代码中的 `Node*& head` 是指向节点的指针的引用，让函数能够修改调用方的头指针。示例是函数片段；复制到完整 C++ 程序时还需节点定义，遍历中的 `cout` 需 `<iostream>` 与 `using std::cout;`。所有位置均从 1 计数。

### 实现与复杂度

`linked-list-core.js` 使用 `nodes` 节点表、稳定 ID 引用 `next` 和 `head` 建模。算法从 head 沿 next 寻找节点，不使用数组插删或倒序来冒充链表操作。生成器每次输出不可变快照、临时指针、角色标签、说明和准确的 C++ 行号。

`linked-list.js` 管理单定时器、任务编号和操作前快照，并将所有存活节点及其真实箭头绘制出来。布局数组只决定卡片位置。新节点和待释放节点可暂放在旁边；反向箭头从节点底部绕行。卡片与 SVG 使用同一个固定坐标系，窄屏通过画布内部滚动查看，不会压缩节点。逐步更新采用离散状态，保证暂停和单步时没有后台位移动画继续改变画面。

遍历、查找、反转最坏时间均为 O(n)。按位置插入/删除的寻找前驱成本为 O(n)，修改引用本身为 O(1)，因此整体最坏为 O(n)，头插/头删为 O(1)。这些算法本身只需 O(1) 辅助空间（新建一个节点另需 O(1)）。网页为绘图、访问记录和当前快照使用 O(n) 额外空间；每步复制节点的工作不计入链表算法本身的复杂度。当前实现按需生成步骤，不保留全部历史；若将来存储 O(n) 个完整快照，历史记录可达到 O(n²) 空间。

## 实现思路：算法和播放分开

### 先阅读这三个位置

1. **`parseArray(text)`**：把输入拆成数字，检查数量、整数格式和范围。先完整校验再替换数组，避免输入错误破坏原数据。不能用 `parseInt()` 直接校验，因为它会把 `2abc` 截断成 `2`。
2. **`bubbleSortSteps(input)`**：使用与 C++ 相同的两层循环。`function*` 定义生成器，`yield` 暂停函数并交出一个步骤；播放器调用 `.next()` 才执行下一步。比较和交换分别产生步骤，不交换也会产生说明。没有使用内置 `sort()` 实现排序。
3. **`scheduleNext()` / `advanceStep()`**：一次只用一个 `setTimeout` 安排下一步，在回调中读取生成器并更新画布。旁边的 `togglePause()`、`cancelPlayback()` 和 `reset()` 管理暂停、取消和恢复。

### 数据怎样流动

```text
输入 → parseArray 校验 → 当前数组
                            ↓ 开始
                  bubbleSortSteps 生成步骤
                            ↓ next()
                  advanceStep → showStep → 画布与统计
                            ↑
                  setTimeout 等待下一步
```

每个步骤含有数组快照、比较位置、已排序后缀的起点、轮次、累计比较/交换次数和说明。数组快照让已产生的步骤不会被后续交换修改。网页按需消费步骤，不预先保存全部动画帧。

`state` 集中保存当前数组、开始前的数组副本、播放状态、生成器和定时器。状态仅有 `idle`、`running`、`paused`、`completed` 四种。排序和暂停期间锁定数组编辑；同时在事件处理函数中检查状态，防止重复开始。

暂停会清除定时器、冻结 Web Animations 并保留生成器位置。继续后从当前步骤等待一个完整间隔，再执行下一步。重置会递增任务编号 `runId`、清除定时器和动画；旧回调即使已排队，也无法通过编号检查。

柱高为 `数值 / 当前最大值 × 210px`。画布固定高度，数值始终显示在柱子上方。交换时保留柱子对应的 DOM 节点，通过 Web Animations 从旧位置移动到新位置。系统选择“减少动态效果”时省略位移动画，算法步骤不变。

### 几个操作约定

- 修改输入框后，需要按「应用数组」或在输入框按 Enter，才会更新画布。
- 「重置」恢复到**本次点击开始前**的数组，并清零统计；应用新数组或随机数组后，也会将其设为新的起点。
- 完成后「再次排序」会排序画布上当前的数组，所以一般会在第一轮提前结束。要重看刚才的过程，先「重置」，再「开始排序」。
- 调速对后续步骤生效，已经安排好的当前等待不会突然跳过。
- 图上的轮次从 1 开始，下标从 0 开始；待开始时轮次显示 0。

## 已知限制

- 网站包含冒泡排序、无哨兵单链表与二叉树四种遍历。冒泡排序没有单步按钮；链表与二叉树支持单步。三个模块均没有历史回放或持久化，刷新页面恢复默认数据。
- 二叉树最多 15 个实际节点；深树允许局部纵向滚动。第一阶段不包含拖拽编辑、插删节点、翻转、对称性、直径、最近公共祖先等操作；最大深度仅作为创建后的结构信息展示。
- 步骤间隔是目标时间，后台标签页、设备性能或浏览器节流可能延长等待。
- 支持现代浏览器，主要以 Microsoft Edge 验收；未针对旧版 Internet Explorer 做兼容处理。
- 冒泡排序本身平均和最坏时间复杂度为 O(n²)，有提前退出时最好为 O(n)。C++ 原地算法额外空间为 O(1)；网页为数组副本、步骤快照和柱子节点使用 O(n) 额外空间。
- 20 个逆序元素需 190 次比较和 190 次交换；最慢速度下整个演示需要数分钟，这是逐步展示的正常结果。
